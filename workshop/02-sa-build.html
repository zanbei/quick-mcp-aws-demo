    SA 一键搭建 DB / 数仓 / RAG / MCP Server

    用 AWS CLI 脚本把三类数据源和企业入口搭好：Redshift 数仓、RDS PostgreSQL 数据库、Bedrock 知识库（RAG），以及 Cognito + AgentCore Gateway + Lambda 组成的 MCP Server。

    📋 前置条件

    为了完成本 module，需要您准备以下信息，用于下面的四段搭建流水线：

    • 一个具备建权的 AWS AWS_PROFILE（能创建 IAM、Lambda、Cognito、Secrets Manager、S3 / S3 Vectors、Bedrock KB、AgentCore Gateway、Redshift Serverless、RDS），用于全部创建命令
    • 区域（默认 us-east-1）与资源前缀 NAME_PREFIX（默认 quick-mcp-demo），用于资源命名与打标签
    • 本机工具 aws CLI、uv、Python 3.10+，用于运行脚本
    • 仓库里的 AGENTS.md，用于交给 Kiro 按序执行（下一步说明怎么给）
    🎯 目标输出

    四个阶段 Gate 全部通过后，您将得到以下值，用于模块 3、4 填写 Quick 连接器字段。注意“怎么拿到”——脚本会 echo 一部分，另一部分存在 Secrets Manager / 需要单独查一条命令（示例格式仅供对照）：

    方式 B — 阶段 1：Redshift（数据仓库）

    步骤 3–7 是方式 B（手动逐阶段）的具体命令与验收（Gate）。选了方式 A（交给 Kiro）的话，这些由 Kiro 代跑，这几页仅供查阅与核对。

    ✅ Gate

    ID=$(aws redshift-data execute-statement --workgroup-name "$RS_WORKGROUP" --database "$RS_DB" \
  --sql "SELECT COUNT(*), SUM(revenue) FROM public.demo_sales" --query Id --output text)
sleep 8; aws redshift-data get-statement-result --id "$ID" --query Records --output json

    期望 2600 和 1197156.76。

    模块 2 · 步骤 4 · 阶段 2

    RDS PostgreSQL（关系型数据库）

    bootstrap/create_rds.sh create               # 约 5–10 分钟；加密、密码托管、永不对外
export RDS_ID=${NAME_PREFIX}-pg RDS_INSTANCE=${NAME_PREFIX}-pg RDS_DB=demo
uv run --no-project --isolated --with boto3 python scripts/seed_rds_private.py seed

    产出

    • 一个非公网可访问的加密 RDS PostgreSQL 实例，密码托管在 Secrets Manager。
    • 同样的两张表与 2600 行数据（在 VPC 内由临时 Lambda 注入，不开任何入站端口）。
    • 只读角色 mcp_readonly 和密钥 <NAME_PREFIX>/pg-readonly，供后续 Lambda 连库使用。
    • 安全组 <NAME_PREFIX>-pg-lambda-sg 及其对 RDS 5432 的放行规则。

    ✅ Gate

    脚本输出 demo_sales rows / total revenue: (2600, Decimal('1197156.76'))，并按类别列出 Subscription 620058.00、Devices 374181.22、Smart Home 202917.54。确认未对外开放：

    aws rds describe-db-instances --db-instance-identifier "$RDS_ID" \

    模块 2 · 步骤 6 · 阶段 4

    企业入口（Cognito + Gateway + Lambda = MCP Server）

    cd agentcore-verify
./setup.sh                      # Cognito、Gateway、Redshift Lambda 目标（需 RS_WORKGROUP/RS_DB/WG_ID）
uv run --no-project --isolated --with 'mcp<2' --with boto3 python test_gateway.py

./setup_pg.sh                   # 需 RDS_ID；VPC/子网/安全组从实例读取
uv run --no-project --isolated --with 'mcp<2' --with boto3 python test_gateway_pg.py

./setup_kb.sh                   # 需 KB_ID、KB_REGION
uv run --no-project --isolated --with 'mcp<2' --with boto3 python test_gateway_kb.py

./get_token.sh --check          # 期望 HTTP 200，tools: 11

    产出

    • 一个 Cognito user pool + app client（client_credentials，自定义 scope），凭证存 Secrets Manager。
    • 一个 AgentCore Gateway，挂 3 个 Lambda 目标：Redshift MCP（6 工具）、PostgreSQL MCP（3 工具）、知识库 MCP（2 工具）。
    • Gateway URL（以 /mcp 结尾），Quick 云端连接器用它作统一入口。
    • 最小权限：Redshift 默认只读，RDS 用只读角色，知识库 Lambda 只有对该 KB 的 bedrock:Retrieve。

    ✅ Gate

    get_token.sh --check 返回 200 且 11 个工具（Redshift 6、PostgreSQL 3、知识库 2）；未带令牌的请求返回 401。

    ⚠️ 常见坑（摘自 AGENTS.md）

    • awslabs server 需 mcp 2.x，Lambda 适配器需 mcp 1.x，依赖拆成两套（server_pkgs）。
    • Gateway 的工具 schema 不接受 enum；Lambda 包超 50 MB 必须经 S3 部署。
    • postgres server 启动参数不要加 --db_type，对 RDS 单实例会缺集群 ARN 崩溃。
    • macOS 自带 bash 3.2，没有关联数组；脚本改完用 /bin/bash -n 检查。
